# Домашнее задание: Java Collections

Решение лежит в пакете `org.Zadanie7`. Java 17+, Maven, JUnit 5.

## Как запустить тесты

В корне проекта:

```
mvn clean test
```

Эксперимент из задания 2 запускается отдельно: нужно открыть `CollectionPerformanceExperiment` и запустить метод `main`.

## Результаты эксперимента

Время в наносекундах, 10 000 элементов. Перед замером 2 прогрева, потом 5 замеров, в таблице медиана. Цифры из одного запуска, на другом компьютере они будут другими.

| Операция | Элементов | ArrayList, нс | LinkedList, нс |
|---|---|---|---|
| Добавление в конец | 10000 | 370958 | 123375 |
| Добавление в начало | 10000 | 2646916 | 169292 |
| Вставка в середину | 10000 | 1437875 | 39456375 |
| Доступ по индексу | 10000 | 25667 | 34650375 |
| Удаление из начала | 10000 | 2565042 | 116417 |
| Удаление из конца | 10000 | 33667 | 140000 |

## Выводы

ArrayList хранит элементы в массиве, поэтому доступ по индексу у него почти мгновенный (25 тысяч нс против 34 миллионов у LinkedList).
У LinkedList для каждого `get(i)` нужно идти по цепочке узлов с начала или с конца.
Ещё узлы лежат в памяти вразброс, а массив одним куском, и процессору удобнее читать подряд.
При добавлении и удалении в начале ArrayList должен сдвигать все элементы, поэтому он медленнее: 2,6 млн нс против 0,17 млн у LinkedList.
У LinkedList в начале достаточно поменять пару ссылок. Вставка в середину у LinkedList вышла в разы медленнее: хоть сама вставка дешёвая, до середины сначала надо дойти по узлам.
У ArrayList позиция находится сразу, и сдвиг половины массива выполняется быстро. Удаление с конца у обоих списков быстрое, там сдвигать нечего.
Добавление в конец у LinkedList получилось быстрее, чем у ArrayList, хотя по теории они близки. Возможно, ArrayList тратит время на расширение массива и копирование.
Разница небольшая, и в другом запуске она может измениться. Получается, что «всегда быстрее» ни один список не бывает, всё зависит от набора операций.
